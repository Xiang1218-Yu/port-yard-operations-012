# HarborGrid · 港口集装箱堆场作业协同与闸口调度系统

React + Vite + TypeScript 前端，Node.js + Express + TypeScript 服务端。面向中型集装箱码头，把船期、箱务、堆场区块、闸口预约、设备作业和异常闭环放在同一套作业控制台中。

## 启动

```bash
npm install
npm run dev
```

前端默认 Vite 端口 5178，API 默认 `http://localhost:4107`。

## 业务能力

- 船舶航次、泊位窗口、计划/已完成翻箱和延误风险
- 箱号、尺寸、冷藏温度、危险品级别、海关状态、进出口/中转流向
- 堆场区块容量、堆存热度、冷藏插座、危险品隔离和设备可达性
- 闸口预约时隙、车道、OCR/称重/封志校验状态与同车冲突检测
- 岸桥、场桥、集卡、正面吊设备池和约束感知任务队列
- 自动堆位推荐、冷藏/危险品约束、海关查验阻塞、任务指派审计
- TOS 交换适配层：导入航次/箱务/堆位/作业事件报文，导出本系统任务与闸口状态；批次留痕、字段映射、冲突裁决与失败重试
- React 控制台支持船期驾驶舱、闸口操作、堆场热区、设备任务操作与 TOS 交换差异台

## TOS 交换适配层

外部报文（字段名、枚举、时间格式均不同）经 `server/src/exchange.ts` 映射后才进入领域模型，关键决策：

- **冲突优先级**：本地人工操作优先。实体存在人工审计记录时，外部更新/删除挂起为「待裁决冲突」，调度员在控制台逐条选择接受外部或保留本地，不做全量覆盖。
- **未知枚举隔离**：映射表之外的枚举值（如 `customsStatus: X-RAY`）整条记录隔离，原始报文留存可重试，绝不猜测落地。
- **幂等**：`messageId` + 报文哈希去重（同文重放返回原批次，异文重放拒绝）；记录级按映射内容哈希跳过重复；事件按 `eventId` 去重；堆位按事件时间丢弃过期版本。
- **局部回滚**：每条记录应用前快照、失败仅恢复本条影响，批次内其余记录正常提交，拒绝原因与是否可重试逐条留痕。
- **删除语义**：`deleted: true` 软删除——存在进行中预约或未完成任务时拒绝；删除后留墓碑，后续同键报文视为重新建档并标注。

API：`POST /api/exchange/import`、`POST /api/exchange/export`、`GET /api/exchange/batches[/:id]`、`POST /api/exchange/batches/:id/retry`（支持 `recordIds` 与 `resolutions` 裁决）。

当前使用内存种子数据，领域服务通过 REST API 暴露，后续可接入 TOS、OCR、称重、RTG 遥测、预约配额和优化求解器。
